1. First launch & sign in

Who: Any user · Result: Session opened (or password change required)

flowchart TD
  A[Start MEACH] --> B[Database created / migrated
bootstrap data only]
  B --> C[Sign-in window]
  C --> D[Enter username + password]
  D --> E{Credentials valid?}
  E -->|No| F[Show error] --> D
  E -->|Yes| G{Must change password?}
  G -->|Yes| H[Password change dialog]
  G -->|No| I[Main window MEACH]
  H --> I

Default admin: admin / ChangeMe123!. Release builds do not load demo students or fees.

2. Change password (mandatory)

Who: User flagged Must change password · Result: New password stored; app usable

flowchart TD
  A[After successful login] --> B[Choose a new password]
  B --> C[Enter current password]
  C --> D[Enter new password + confirm]
  D --> E{Policy OK?
8+ chars, letter + digit}
  E -->|No| F[Show validation error] --> D
  E -->|Yes| G[Save]
  G --> H[Enter main window]
  B --> I{Cancel?}
  I -->|Yes| J[Signed out]

3. Commission a new school (master data)

Who: Administrator · Result: School ready to enrol students and bill

flowchart TD
  A[Sign in as admin] --> B[Administration → Settings]
  B --> C[School name, contacts,
currency MGA/Ar, footer]
  C --> D[Save]
  D --> E[People → School years]
  E --> F[Confirm / create year
Set as current]
  F --> G[People → Academic levels]
  G --> H[Confirm L1 L2 L3]
  H --> I[People → Student groups]
  I --> J[Create groups + schedules]
  J --> K[Administration → Payment types]
  K --> L[Adjust default amounts
Add custom types if needed]
  L --> M[Ready for students]

4. Create a student group + schedule

Who: School manager / Administrator · Prerequisite: Academic level exists

flowchart TD
  A[People → Student groups] --> B[Create]
  B --> C[Name + academic level]
  C --> D[Save group]
  D --> E[Select the group]
  E --> F[Schedules → Add session]
  F --> G[Weekday + start / end time]
  G --> H{End after start?}
  H -->|No| G
  H -->|Yes| I[Save session]
  I --> J[Group ready for enrolment
and daily attendance]

5. Enrol a student

Who: School manager / Administrator · Prerequisite: Level, group, open school year

flowchart TD
  A[People → Students] --> B[Create]
  B --> C[First / last name, gender, DOB]
  C --> D[Contacts optional]
  D --> E[Level + group + school year]
  E --> F[Enrolment date + status]
  F --> G[Save]
  G --> H[Student number assigned]
  H --> I[Student appears in list]

6. Transfer a student

Who: School manager / Administrator · Prerequisite: Destination group is active

flowchart TD
  A[Students → select student] --> B[Transfer]
  B --> C[Choose destination group]
  C --> D{Active and different?}
  D -->|No| E[Cannot transfer] --> C
  D -->|Yes| F[Optional reason]
  F --> G[Confirm Transfer]
  G --> H[Group + level updated]

7. Bill Droit for one student

Who: Accountant / Administrator · Result: One unpaid Droit obligation for that year

flowchart TD
  A[Payments → Droit
or Students → Create bill → Droit] --> B[Bill Droit]
  B --> C[Select school year]
  C --> D[Choose One student]
  D --> E[Search and pick student]
  E --> F[Amount = type default
set due date]
  F --> G[Bill the fee]
  G --> H{Already has Droit
this school year?}
  H -->|Yes| I[Skipped — no duplicate]
  H -->|No| J[StudentFee created
Status Unpaid]
  J --> K[Visible on Droit list
and student file]

Rule: Only one Droit per student per school year. School year must be open.

8. Pay a Droit for one student

Who: Cashier / Administrator · Prerequisite: Droit already billed and outstanding

flowchart TD
  A[Start] --> B{Where from?}
  B -->|Shell| C[Register a payment]
  B -->|Droit list| D[Select Droit line → Register payment]
  B -->|Student detail| E[Open student → Register payment]
  C --> F[Search student]
  D --> G[Fee preselected]
  E --> G
  F --> H[Outstanding fees load]
  H --> I[Select Droit line]
  I --> G
  G --> J[Amount = remaining
optional partial]
  J --> K[Date + method
Cash / Mobile money / …]
  K --> L[Optional reference + notes]
  L --> M[Print receipt? usually Yes]
  M --> N[Register]
  N --> O{Possible duplicate?}
  O -->|Yes| P[Confirm to continue]
  O -->|No| Q[Payment + receipt saved]
  P --> Q
  Q --> R[Fee balance updated]
  R --> S[Print receipt if requested]
  S --> T[Done]

End-to-end with billing: Scenario 7 (bill) then Scenario 8 (pay). Partial payments are allowed until remaining reaches zero.

9. Bill monthly Écolage for a group

Who: Accountant / Administrator

flowchart TD
  A[Payments → Écolage] --> B[Generate monthly fees]
  B --> C[School year + months]
  C --> D[Amount per month + due day 1–28]
  D --> E[Entire group / all groups
or One student]
  E --> F[Generate]
  F --> G[For each student × month]
  G --> H{Already billed?}
  H -->|Yes| I[Skip]
  H -->|No| J[Create monthly StudentFee]
  I --> K[Summary: created / skipped]
  J --> K

10. Pay Écolage (partial or full)

Who: Cashier / Administrator

flowchart TD
  A[Register a payment] --> B[Select student]
  B --> C[Pick Écolage month line]
  C --> D{Pay full remaining
or partial?}
  D -->|Full| E[Amount = remaining]
  D -->|Partial| F[Enter amount less than remaining]
  E --> G[Method + date → Register]
  F --> G
  G --> H[Receipt issued]
  H --> I{Remaining = 0?}
  I -->|Yes| J[Fee fully paid]
  I -->|No| K[Still unpaid / partial
pay again later]

11. Bill Livre (book fee)

Who: Accountant / Administrator

flowchart TD
  A[Payments → Livre] --> B[Bill Livre]
  B --> C[School year + target]
  C --> D[Book description required
e.g. Math book]
  D --> E[Amount + due date]
  E --> F[Bill]
  F --> G{Same description
already this year?}
  G -->|Yes| H[Skipped for that student]
  G -->|No| I[New Livre line created]

Many Livre lines per year are allowed when descriptions differ.

23. Close a school year

Who: Administrator

flowchart TD
  A[People → School years] --> B[Select year]
  B --> C[Close]
  C --> D[Year marked closed]
  D --> E[No new bills]
  D --> F[No register / cancel payments
for students on that year]
  B --> G[Reopen if corrections needed]
